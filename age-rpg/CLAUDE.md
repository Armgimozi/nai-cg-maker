# 개발 지침: 친구용 RPG 서버 (가제 "에이지 RPG")

이 폴더에서 일하는 Claude 는 작업을 시작하기 전에 이 문서를 끝까지 읽고 따른다.
사용자가 이 문서와 다르게 말하면 사용자의 말이 앞서고, 정한 것은 `DECISIONS.md` 에 한 줄씩 남긴다.

## 0. 한 줄 요약

친구 2~6명이 같이 하는, **마크에이지 느낌의 RPG** 마인크래프트 서버를 Paper 플러그인 하나 + 서버 리소스팩 + 미리 지은 월드로 만든다.
핵심은 **직업·스킬**, **던전·보스**, **경제·생활**이고, **반복 노가다는 하지 않게** 만든다. 국가전쟁은 없다.

- 마크에이지는 분위기와 재미의 참고일 뿐이다. 이름·로고·문구·그림·직업 이름을 그대로 가져오지 않는다 (2020년에 상표·무단 도용 분쟁이 있었다). 제목에 "마크에이지" 를 쓰지 않는다.
- 접속은 아무것도 깔지 않은 바닐라 자바 클라이언트 + 서버 리소스팩. 모드 없음.

## 1. 사용자와 일하는 방식

- 사용자는 한국인이다. 답은 **한국어 반말**로, 짧게, 할 일 위주로 한다. 시각은 **한국 시간(KST)** 으로 말한다.
- 기다리게 하는 걸 싫어한다. 오래 걸리는 일은 시작할 때 예상 시간을 말하고, 중간에 상황을 알리고, **끝난 것부터 먼저 보낸다** (jar, zip, 스크린샷).
- 늦어지거나 틀렸으면 솔직하게 말한다. 확인하지 않은 것을 됐다고 하지 않는다.
- 진짜로 사용자가 골라야 하는 것만 묻는다 (방향, 취향, 되돌리기 어려운 것). 나머지는 합리적인 기본값으로 정하고 한 줄로 알린다.
- 사용자가 직접 서버를 연다 (Windows PC). 설치·접속 안내는 Windows 기준으로, 메뉴 이름과 눌러야 할 것을 순서대로 적는다.
- 커밋·푸시는 작업 브랜치에만 한다. PR 은 만들지 않는다. 비밀 값(API 키, `config.json`)은 절대 커밋하지 않는다. 커밋·문서에 모델 이름을 쓰지 않는다.

## 2. 설계 원칙 (모든 기능이 지켜야 한다)

### 2.1 노가다 금지 (가장 중요)

같은 행동을 오래 반복해야만 앞으로 갈 수 있는 구조를 만들지 않는다. 기능을 만들 때마다 아래를 확인한다.

1. **목표 시간**: 처음 접속부터 만렙·최종 보스까지 친구 3명 기준 **약 25~35시간**. 레벨 하나에 30분 넘게 걸리는 구간이 없게 한다.
2. **다양한 경험치**: 사냥만이 아니라 퀘스트, 던전 첫 클리어, 보스, 탐험(새 지역·숨은 장소 발견), 생활 기술 첫 제작에서도 경험치를 준다. 사냥 비중은 전체의 절반 이하.
3. **같은 짓 반복 감쇠**: 같은 종류 몹을 10분 안에 많이 잡으면 경험치·드롭이 줄어든다 (예: 30마리부터 50%, 60마리부터 20%). 다른 일을 하면 바로 회복된다. 대신 그 사실을 액션바로 알려 준다 ("같은 사냥감이 지겨워진다 — 다른 곳으로 가 보자").
4. **운 보정(천장)**: 확률 드롭에는 반드시 천장을 둔다. 보스 장비는 최대 N번(기본 5번) 안에 확정. 던전마다 **던전 주화**를 주고 상점에서 원하는 장비와 바꿀 수 있게 한다. 1% 미만 드롭 금지.
5. **파티 친화**: 같이 싸운 사람은 모두 **각자** 경험치와 보상을 받는다 (나눠 먹지 않는다). 뒤처진 친구는 따라잡기 보너스(예: 파티 평균보다 5레벨 낮으면 경험치 1.5배).
6. **이동 노가다 없음**: 마을·던전 입구·지역마다 이동 지점(워프석). 처음 한 번 걸어가면 이후 바로 이동.
7. **퀘스트 문구**: "○○ 100마리" 같은 목표 금지. 처치 목표는 15마리 이하, 대부분은 대화·탐험·전투 한 번·제작 같은 다른 목표로.
8. **생활 기술**: 높은 단계는 "만 번 반복"이 아니라 레시피(던전·보스·퀘스트 보상)로 연다. 숙련도는 다양한 재료·제작에서 오른다.
9. **매일 숙제 없음**: 일일·주간 의무 콘텐츠를 만들지 않는다. 쉬었다 와도 손해가 없게.

### 2.2 그 밖의 원칙

- **운보다 실력·선택**: 전투 효과(치명타 등)는 확률 대신 "N번째 공격마다" 처럼 정해진 방식으로 (예전 스카이블럭에서 친구들이 더 좋아했다).
- **보스는 피할 수 있게**: 강한 공격은 반드시 예고(바닥 표시 입자, 소리, 자세)가 먼저 나온다. 체력만 많은 보스 금지 — 보스마다 피하기·끊기·위치 잡기 같은 기믹이 하나 이상.
- **인원 보정**: 던전·보스는 들어온 인원(1~6명)에 따라 체력·피해가 자동으로 맞춰진다 (예: 체력 ×(0.6 + 0.4×인원)). 혼자서도 깰 수 있고 여럿이면 더 빠르다.
- **게임 안에서 다 알 수 있게**: 안내서(책)·메뉴·도감으로 직업, 스킬, 지역, 던전, 제작법을 볼 수 있다. 위키를 봐야만 알 수 있는 정보 금지. 모든 문구는 한국어.
- **데이터로 바꿀 수 있게**: 직업·스킬·몹·아이템·던전·퀘스트·상점은 YAML 로 정의하고 코드 수정 없이 수치를 바꿀 수 있게 한다.

## 3. 만들 것

### 3.1 직업과 스킬 (마크에이지 느낌의 중심)

- 시작 직업 6개 (이름은 새로 짓는다). 역할이 겹치지 않게:
  | 역할 | 예시 콘셉트 | 무기 |
  |---|---|---|
  | 근접 딜러 | 검과 연속 베기 | 검 |
  | 탱커 | 방패·도발·보호막 | 도끼/망치 + 방패 |
  | 원거리 딜러 | 활·덫·관통 | 활 |
  | 마법 딜러 | 원소 마법·범위 | 지팡이 |
  | 회복·지원 | 치유·정화·버프 | 성물 |
  | 암살자 | 순간이동·은신·약점 | 단검 |
- 레벨 30에 **2차 전직** (직업마다 두 갈래 중 하나). 전직은 퀘스트 한 번으로, 노가다 없이.
- 직업마다 스킬 **5개 + 궁극기 1개 + 패시브 2개**. 레벨에 따라 열린다 (1, 5, 10, 15, 20, 궁극기 25).
- **입력** (바닐라 클라이언트로 가능한 조합만): 우클릭, 웅크리기+우클릭, 웅크리기+좌클릭, F(손 바꾸기, 이벤트를 막고 스킬로), 단축 슬롯 1~3 을 "스킬 슬롯"으로 쓰는 방식 중에서 정한다. 무기를 든 상태에서 일반 공격과 겹치지 않게. 스킬 이름·남은 재사용 시간은 액션바에 보여 준다.
- **자원**: 마나(또는 직업별 기력) 막대를 화면에 보여 준다 (경험치 막대를 빌리거나 리소스팩 글꼴 HUD).
- **스킬 연출은 입자로** (마크에이지식): 두께 있는 초승달 베기 궤적, 날아가는 검기, 회오리, 충격파 고리, 나선 빛기둥, 블록 파편. 바닥 마법진 그림 같은 리소스팩 평면 그림은 쓰지 않는다 (사용자가 싫어했다).
  - 레벨·장비 등급이 높을수록 겹·굵기·양이 늘어 화려해진다. 궁극기는 확실히 화려하게.
  - **시전자 1인칭 화면을 가리는 입자는 시전자에게 보내지 않는다** (눈 앞 2~3칸, 오래 떠 있는 밝은 입자).
  - 표시 엔티티를 쓰면 저장 안 되게(persistent false), 태그를 붙이고, 수명이 끝나면 반드시 지운다. 서버 시작 때 남은 것도 청소.
  - 땅에 반쯤 묻혀 나오는 블록 표시는 빛이 0 이라 새까맣게 보인다 → 한 칸 위 빛을 쓰거나 밝기를 고정.

### 3.2 레벨·능력치·장비

- 만렙 50. 필요 경험치는 완만한 곡선 (예: `100 × L^1.5`). 2.1 의 목표 시간에 맞춰 조정하고, 조정 근거를 `DECISIONS.md` 에 남긴다.
- 능력치는 단순하게: 레벨로 자동 성장 + 장비. 찍는 스탯 포인트를 넣는다면 다시 찍기를 공짜로.
- 장비 등급 5단계 (일반·고급·희귀·영웅·전설), 세트 효과, 3D 모델(리소스팩). 무기 종류는 직업과 묶는다.
- **강화** +1~+10: 재료와 골드를 쓰고, **실패해도 아이템이 부서지거나 단계가 내려가지 않는다** (실패하면 다음 성공 확률이 오르는 천장 방식).
- 내구도는 가볍게 (수리가 귀찮은 숙제가 되지 않게). 마을에서 골드로 수리.

### 3.3 월드

- 미리 지어서 배포하는 월드. 지형은 바닐라 생성 + 플러그인이 마을·던전 입구·랜드마크를 짓는다 (또는 손으로 설계한 배치를 코드로 짓는다).
- **마을(안전 지대)**: 직업 교관, 상점, 대장간(강화·수리), 거래소, 창고, 이동 지점, 퀘스트 게시판.
- **지역 5개** (레벨대별): 예) 초원 1–10, 숲 10–20, 사막 20–30, 설산 30–40, 화산 40–50. 지역마다 몬스터 4~6종, 고유 재료, 던전 입구 1개, 숨은 장소 몇 곳(발견 경험치).
- 지역 사이는 걸어서도 갈 수 있지만, 한 번 간 곳은 이동 지점으로.

### 3.4 몬스터·던전·보스

- 일반 몬스터: 바닐라 몹을 바탕으로 이름·장비·능력치·스킬을 입힌다. 일반 몹 이름표는 숨긴다 (거슬렸다). 정예 몹만 이름표.
- **던전 5개 + 최종 레이드 1개**. 던전은 파티 전용 **인스턴스** (들어갈 때마다 템플릿을 복사한 공간, 끝나면 정리).
  - 구성: 잡몹 구간 2~3개 → 중간 보스 → 최종 보스. 15~25분.
  - 보스마다 기믹 1~2개 + 예고 있는 강공격 + 체력에 따른 단계 변화.
  - 보상: 각자 개인 보상, 첫 클리어 보너스, 던전 주화(천장 교환).
- 필드 보스는 선택 사항. 넣으면 30분 재등장, 둥지 밖으로 끌고 가면 돌아간다.

### 3.5 경제·생활

- **골드**: 플러그인 안에서 관리하는 화폐 (외부 경제 플러그인 없이). 몬스터·퀘스트·판매로 번다.
- **골드 쓸 곳(소모처)**: 강화, 수리, 이동, 상점, 레시피. 골드가 넘쳐 의미 없어지지 않게 소모처를 꼭 만든다.
- **NPC 상점**: 사고팔기 창(인벤토리 GUI).
- **거래**: 플레이어끼리 1:1 거래 창 + 작은 거래소(올려 두고 사기).
- **생활 기술 4개**: 채광, 채집(약초·나무), 낚시, 제작(요리·물약·장비 재료). 각자 레벨이 있고, 결과물이 전투에 쓸모 있어야 한다 (음식 버프, 물약, 강화 재료, 희귀 장비 제작).
- 개인 집/섬은 선택 사항 (넣으면 나중 마일스톤).

### 3.6 퀘스트·안내

- 메인 퀘스트 줄기가 지역 순서대로 플레이어를 이끈다 (레벨 1→50). 직업 퀘스트(전직), 지역 퀘스트 몇 개.
- NPC 대화는 채팅 대신 보기 좋은 창 또는 책. 진행 중 목표는 사이드바(스코어보드)에.
- 시작 때 안내서 책을 준다. 위치를 대놓고 알려 주는 표시(빛기둥·좌표)는 쓰지 않는다 (사용자 취향). 대신 퀘스트가 방향을 말로 안내한다.

### 3.7 PvP

- 기본은 협동. PvP 는 결투(서로 동의) + 투기장. 필드 PvP 는 설정으로 켜고 끈다.
- 플레이어끼리는 스킬 추가 피해를 줄인다 (설정, 기본 0.5배). 즉사 효과는 플레이어에게 쓰지 않는다.

### 3.8 화면(UI)

- 액션바: 스킬 재사용, 콤보, 알림. 보스바: 보스 체력·단계.
- 사이드바: 레벨, 경험치 %, 골드, 진행 중 퀘스트.
- 메뉴(인벤토리 GUI): 직업·스킬, 능력치, 퀘스트, 도감, 상점, 거래, 강화, 창고. 모두 한국어, 아이템 설명(로어)은 짧고 읽기 쉽게.

## 4. 기술 지침

- **서버**: Paper (시작할 때 최신 안정판을 확인해서 고정하고 `DECISIONS.md` 에 적는다. 친구들 클라이언트 버전과 맞춘다). Java 21, Gradle, 플러그인 하나 (외부 플러그인 의존 없음).
- **콘텐츠는 YAML**: `classes.yml`, `skills.yml`, `items.yml`, `mobs.yml`, `dungeons.yml`, `quests.yml`, `shops.yml`, `recipes.yml`. 콘텐츠 판 번호(`CONTENT_VERSION`)를 두고, 올리면 기존 서버의 옛 YAML 을 옆으로 옮기고 새 것을 꺼낸다. 플레이어 손에 있는 아이템도 접속·손에 들 때 새 정의로 갱신한다.
- **저장**: 플레이어별 파일(YAML) 또는 SQLite. 주기적 자동 저장 + 종료 시 저장. 서버가 갑자기 꺼져도 크게 잃지 않게.
- **리소스팩**: 파이썬 스크립트로 생성(모델·텍스처·글꼴 HUD). 플러그인이 작은 HTTP 서버로 직접 보내고(기본 포트), 터널(playit.gg) 환경을 위해 `resource-pack.url` 에 외부 주소(예: GitHub raw, **커밋 고정 주소**)를 넣을 수 있게. 팩이 바뀌면 주소도 바뀐다는 걸 사용자에게 꼭 알린다.
- **성능**: 6명 기준. 틱당 입자·엔티티 상한을 둔다. 보이지 않는 곳의 연출은 보내지 않는다.
- **배포물**: `dist/` 에 jar, 서버 zip(서버 폴더 + 월드 + 플러그인 + 리소스팩), 리소스팩 zip. 묶는 스크립트가 월드·데이터가 맞는지 검사하고 틀리면 멈춘다.

### 4.1 가져다 쓸 것 (같은 저장소 `augment-skyblock/`)

새로 짜기 전에 먼저 읽고 필요한 만큼 옮긴다 (패키지 이름은 새 프로젝트에 맞게).

| 무엇 | 어디 | 쓰임 |
|---|---|---|
| 스킬 엔진 (cone, nova, projectile, beam, dash, leap, blink, rain, strike, chain, zone, orbit, vortex, summon…) | `plugin/.../skill/` (`Mechanics`, `SkillContext`, `HitEffects`, `Targets`, `Combat`) | 데이터로 정의하는 스킬 |
| 입자 스킬 연출 (등급별 화려함, 1인칭 보호, 정리) | `plugin/.../vfx/` | 3.1 의 연출 |
| 커스텀 몹·보스(둥지, 재등장, 끌고 가면 복귀), 3D 보스 리그 | `plugin/.../mob/` | 3.4 |
| 3D 무기·갑옷 모델 파이프라인 | `pack/wkit.py`, `pack/mc3d.py`, `pack/gen_pack.py` | 장비 모델 |
| Windows 시작기 | `server/start.bat`(ASCII) → `server/start.ps1`(UTF-8 BOM) | 아래 4.2 |
| 배포 묶기 | `tools/make_dist.py` | 서버 zip |
| 내구도·모루·수리 규칙, 아이템 갱신 | `plugin/.../item/` (`Gear`, `ItemGuard`) | 3.2 |

`soulslike/` 프로젝트의 HUD(글꼴 막대), 실제 클라이언트 촬영 도구(`tools/client/`), 봇 시험(`tools/bots/`)도 참고한다.

### 4.2 예전에 겪은 함정 (다시 겪지 말 것)

- Windows 배치 파일에 한국어를 쓰면 일부 PC 의 cmd(CP949)에서 조용히 죽는다 → `start.bat` 은 ASCII 로 PowerShell 스크립트만 부르고, 실제 일은 `start.ps1`(UTF-8 BOM)이 한다. 실행 기록은 `start-log.txt` 에 남긴다.
- EULA 동의 입력에서 한글 자판이면 `y` 가 `ㅛ` 로 들어온다 → `ㅛ`, 예, 네도 받는다.
- Paper 다운로드가 일부 네트워크에서 TLS 오류로 실패한다 → curl `--http1.1 --tls-max 1.2` 재시도, 그래도 안 되면 VPN 안내.
- 서버 폴더를 다시 깔면 op 가 사라진다 → 관리자 명령은 콘솔에서도 되게, 안내문에 `op 닉` 을 적는다.
- 친구 접속: 다른 집 친구는 공유기 때문에 그냥은 못 들어온다. 안내는 playit.gg(서버 주인만 설치) 또는 포트포워딩. 터널은 리소스팩 포트를 못 열므로 팩 외부 주소가 필요하다.
- 인증 서버 연결 실패("인증 서버에 연결할 수 없습니다")는 클라이언트 쪽 네트워크 문제다.
- 일반 몹 이름표가 다 보이면 거슬린다. 정예·보스만.
- 확률 전투 효과는 친구들이 싫어했다 → 정해진 횟수 방식.
- 입자는 시전자 1인칭에서 거대한 얼룩이 된다 → 시전자에게 빼기.
- 서버 `server.properties` 기본값(pvp, 접속 방식)은 처음부터 정해서 배포한다. 바꾸면 기존 서버에는 안 들어간다는 걸 알린다.
- `README.txt` 처럼 Windows 메모장으로 볼 파일은 UTF-8 BOM + CRLF 를 지킨다.

## 5. 시험 (확인하지 않은 건 됐다고 하지 않는다)

- 빌드: `./gradlew build -q --offline` (또는 첫 빌드는 온라인).
- 시험 서버: 고정한 Paper 로 깨끗한 폴더에서 띄우고 RCON 으로 조작. 다른 작업과 포트가 겹치지 않게.
- 봇 시험 (mineflayer): 직업 고르기, 스킬 시전(피해·재사용·마나), 퀘스트 진행, 던전 입장·클리어·보상, 거래, 강화, 저장/재접속. 결과를 숫자로 확인한다.
  - 1.21.x mineflayer 주의: 웅크리기는 `entity_action` 패킷을 직접 보내야 하고, 액션바는 raw `action_bar` 패킷으로만 받는다.
- 눈으로 봐야 하는 것(스킬 연출, 모델, HUD, 창)은 **실제 클라이언트**(Xvfb)로 찍어서 직접 보고 고친다. 고친 전후를 사용자에게 보여 준다.
- 성능: 6명이 동시에 스킬을 쓰는 상황을 봇으로 만들어 틱 시간(MSPT)을 잰다.
- 배포 zip 을 그대로 풀어서 켜 보는 연기 시험을 매 배포마다 한다.

## 7. 밸런스 기준 (처음 값. `config.yml` 로 바꿀 수 있게)

- 일반 몹: 같은 레벨 플레이어가 기본 공격 3~6번에 잡는다. 정예: 15~25초.
- 던전 보스: 적정 레벨 3인 파티 기준 3~6분. 혼자면 8~12분.
- 플레이어 체력: 레벨 1 에 20, 50 에 약 120 (장비 포함 더).
- 보스 강공격: 적정 장비 기준 한 방에 최대 체력의 30~45% (예고를 보고 피하면 0).
- 장비 드롭: 보스 개인 드롭 확률 25% 이상 + 5번 천장. 전설은 최종 레이드 확정 1개.
- 골드: 레벨당 강화 비용 ≈ 그 레벨대 1시간 벌이의 40%.

## 8. 문서

- `README.md`: 사용자용 (설치, 접속, 친구 초대, 문제 해결). 한국어.
- `DESIGN.md`: 전체 명세 (이 문서의 3장을 구체화한 것). 단계마다 갱신.
- `DECISIONS.md`: 사용자와 정한 것, 정한 이유. 문서와 다르면 이쪽이 앞선다.
- `server/README.txt`: 서버 폴더에 들어가는 안내 (UTF-8 BOM + CRLF).
