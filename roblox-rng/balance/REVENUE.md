> 요청: "게임 예상 수익" · 그리고 "방문수 0 실화냐"
> 결론: **방문 0은 지금 규칙에서는 이상한 일이 아닙니다(공개 3일째, 아직 16+ 에게만 보이는 평가 단계, 추천 노출 0).
> 지금 수익은 0이고, 게임은 사람이 들어와야 돈이 됩니다. 1,000 DAU 가 한 달 유지되면 개발자 몫은 월 약 $123(비관 $33 ~ 낙관 $412).**

> 전용 + 평가 단계라면 DAU 0~10, **월 $0~1(낙관 약 $4)** 입니다. 그러면 DevEx 최소 인출액($114)까지 기본으로 8년쯤 걸립니다.
> 숫자는 모두 [`tools/balance/revenue_model.py`](../tools/balance/revenue_model.py) 가 만든 것이고(상품·가격은 `Config.luau` 에서
> 읽음), 전체 값은 [`revenue_results.json`](revenue_results.json) 에 있습니다. 조사 날짜는 2026-09-30입니다.
> **[가정]** 은 제가 정한 값, **[제3자]** 는 로블록스가 아닌 곳의 추정치, S 번호는 끝의 출처입니다.
> 비관·기본·낙관은 **리텐션과 수익화를 한 묶음**으로 바꾼 시나리오입니다(좋은 게임은 둘 다 좋고, 나쁜 게임은 둘 다 나쁨).

   13~17세의 3/5로 친 추정). RNG·타이쿤 장르의 주 고객층이 바로 이 연령대라서 지금은 가장 큰 손님층이 이 게임을 아예 볼 수 없습니다.

## 2. 모델

한 달(30일) 동안 DAU 가 그대로 유지된다고 보고 계산합니다.

- **시나리오 = 리텐션 + 수익화 한 묶음.** 비관은 둘 다 나쁘고, 낙관은 둘 다 좋습니다.
- **수명 활동일 L** = 1 + Σ R(d). R(d) 는 D1·D7·D30 을 지나는 거듭제곱 곡선(180일까지, 30일 뒤는 7→30일 기울기를 이어 붙임)입니다.
- **새 사용자 / 달** = DAU × 30 / L (그 DAU 를 유지하려면 이만큼 새로 들어와야 함)
- **결제자 / 달** = 새 사용자 × 평생 결제 전환율
- **결제자 1인** = 패스마다 "살 확률" + 개발자 상품마다 "평생 몇 번"
- **수명이 길면 더 삼**: 전환과 개발자 상품 개수는 기준 수명 L_REF(= S7 중앙값 리텐션, 1.78일)에서 정한 값이고,
  전환 × (L / L_REF)^0.8, 상품 개수 × (L / L_REF)^0.7 로 늘어나거나 줄어듭니다 [가정]. 패스는 한 번만 사므로 그대로입니다.
  그래서 DAU 를 고정하고 리텐션만 바꾸면 1,000 DAU 당 **$122(비관) / $123(기본) / $131(낙관)** 으로, DAU 당 수익은 거의 그대로이고
  리텐션이 좋을수록 조금 오릅니다. 리텐션의 큰 효과는 같은 유입으로 DAU 가 커지는 쪽에서 옵니다(5장).
- **플레이어가 쓴 Robux** = Σ 개수 × 가격 × 실현율. 패스는 지역 가격이 기본으로 켜져 있어 실현율 75 / 85 / 95%, 개발자 상품은 지역
  가격이 꺼져 있어 100% 입니다.
- **개발자 몫** = 위 × 70% · **Creator Rewards** = DAU × Active Spender 비율 × 자격(10분+, 첫 3개 게임) × 5 R$ × 30
- **USD** = (개발자 몫 + Creator Rewards) × $0.0038

## 5. 무엇이 가장 크게 움직이나 (민감도)

기본 시나리오, DAU 5,000(월 $616)에서 하나씩만 바꿨습니다. 리텐션은 **유입(새 사용자/일)을 고정**하고 바꿨으므로 DAU 도 함께 변합니다.
리텐션이 좋으면 추천 알고리즘이 더 보여 주는 효과는 **빼고** 계산했습니다. 실제로는 리텐션 쪽이 이보다 더 큽니다.

| 바꾼 것 | 나쁘게 | 좋게 |
|---|---|---|
| **리텐션 D1·D7·D30** (180일 수명) | 6%·0.8%·0.2% → **-25%** | 16%·4.5%·2% → **+129%** |
| 리텐션, 수명을 30일까지만 셀 때 | 비관 → -16% | 낙관 → +54% |
| 결제 전환율 | ×0.5 → -44% | ×2 → +89% |
| 결제자 1인 구매 개수 | ×0.6 → -36% | ×1.6 → +53% |
| 패스 지역 가격 실현율 | 75% → -7% | 95% → +7% |
| 10분+ 플레이(Creator Rewards) | 15% → -6% | 50% → +7% |
| 모든 가격 | +25% → -6% | -25% → +8% |

- **리텐션 효과의 절반 넘게가 30일 뒤 꼬리에서 옵니다.** 낙관 곡선은 첫날을 뺀 수명의 58% 가 31~180일(D180 약 0.7%)이고, 이 꼬리는
  7→30일 기울기를 그대로 이어 붙인 가정입니다. 30일까지만 세면 +129% 가 +54% 로 줄어듭니다. 두 값 사이가 현실적인 범위입니다.
- **"가격은 거의 안 움직임"은 발견이 아니라 가정의 결과입니다.** 가격 탄력성을 1.3(1 에 가까움)으로 정했기 때문에 가격을 바꿔도
  수익이 거의 안 변합니다. 가격 최적화 중앙값 +4% [S6] 로는 탄력성을 정할 수 없습니다. 가격은 라이브 뒤 데이터로 판단합니다.
- 리텐션은 이 표에서도 1등이고, 여기에 더해 **DAU 자체(추천)** 를 정합니다. 그래서 돈을 벌려면 리텐션이 먼저입니다.

## 7. 라이브 뒤에 볼 것 (분석)

2~4주 동안, 새 사용자가 1,000명 이상 쌓인 뒤에 봅니다 [가정: 그보다 적으면 잡음이 큼]. 무엇을 보내고 Creator Hub 어디서 읽는지는
[DESIGN.md](../DESIGN.md) "분석" 에 있습니다. 아래 기준으로 시나리오를 고르고
이 문서의 숫자를 다시 맞춥니다(`SCENARIOS` · `RETENTION` 값만 바꿔서 다시 실행하면 됩니다).

| 어디서 | 지표 | 비관 / 기본 / 낙관 기준 | 나쁘면 먼저 할 것 |
|---|---|---|---|
| Creator Hub → Audience Reach | 평가 진행(highly engaged 16+ 플레이 / 250) | 60일 안에 250 | 늘지 않으면 0장 2·3번(영어, 첫 16+ 플레이어) |
| Creator Hub → 리텐션 | D1 · D7 · D30 | 6 / 10.3 / 16% · 0.8 / 1.6 / 4.5% · 0.2 / 0.5 / 2% | D1 < 6% → 첫 5분(온보딩) |
| Creator Hub → 참여 | 세션 길이, DAU 1인 플레이 시간 | 9.8분이 전체 중앙값 [S7], 이 모델은 하루 20분 | < 8분 → 초반 목표·AUTO 안내 |
| Creator Hub → 수익화 | **ARPDAU** · 결제 전환 · ARPPU | **0.36 / 1.37 / 4.76 R$** · 0.32 / 0.86 / 2.78% · 113 / 160 / 171 R$ | ARPDAU 부터 봄(전환·ARPPU 로 나누는 비율은 불확실 — 2장). 전환 < 0.3% → 스타터 팩·상황별 제안 |
| Creator Hub → 유입·추천 | 노출, 클릭률(플레이 비율), 홈 추천 노출, 출처(검색·홈·광고) | 홈 추천 노출이 0에서 벗어나는 날 | 노출은 있는데 클릭이 낮으면 아이콘·썸네일 |
| 분석 퍼널: 온보딩 (`src/server/Analytics.luau`) | 처음 들어옴 → 첫 굴림 → 첫 새 명소 → 첫 전시 → 첫 강화 → 첫 1/1,000 → 첫 환생 | 첫 굴림 ≥ 90% [가정], 첫 환생(무료 중앙값 17분)까지 가는 비율 | 가장 크게 빠지는 단계 한 곳부터 |
| 분석 퍼널: 상점 · 구매 | 상점 열기 → 카드 누름 → 구매 창 → 구매 (상품별) | 상품별 구매 창 → 구매 비율 | 누르고 안 사면 가격·설명, 안 누르면 노출 위치 |
| 분석 퍼널: 환생 · 도장, 사용자 지정 이벤트(SessionEnd · CollectionOpened · AutoOn 등) | 환생 1→10, 접속 시간 구간(처음 온 접속 = 필드 2 First), 도감을 여는 사람 비율 | 시뮬레이터 속도(PROPOSAL.md)와 비교 | 너무 빠르거나 느린 구간 |
